# Что чинить в отчёте бота — инструкция

## Приоритет 1 — Качество извлечения текста

Задача разделяется на **две независимые**: точность распознавания и очистка от служебных
блоков. Одна другую не заменяет.

### 1.1. Бенчмарк распознавания

**Эталон.** Вручную выверенная выборка 20–30 ФЗ — готовится один раз. Это разовый
бенчмарк, а не runtime-проверка (при наличии эталона OCR был бы не нужен).

**Выборка должна быть разнородной:**
- свежие и старые (акты 2010-х заметно хуже по качеству скана);
- одностраничные и на 100+ страниц;
- с таблицами и без;
- разного качества скана (чистые и с артефактами, перекосами, печатями поверх текста).

**Что сравнивать:** несколько OCR-движков + вариант «OCR + постобработка LLM».

**Метрики — раздельные, не одна общая:**

| Метрика | Что меряет | Порог |
|---|---|---|
| CER / WER по тексту | Общая точность распознавания | ≥ 98% |
| **Критичные элементы** | Числа, даты, суммы, сроки, номера статей и пунктов | **100%** |
| Доля служебного мусора | Подписи, печати, реквизиты в выдаче | → 0 |

> **Почему 98% недостаточно как единственный порог.** Для юридического текста 2% ошибок —
> это не «почти идеально»: на статье в 3000 знаков это ~60 неверных символов. Если хоть
> один попал в число, дату или номер статьи — сводка соврёт юридически. Отсюда отдельное
> требование 100% по критичным элементам; не выполнено → карточка флажится.
> Это стыкуется с гейтом №2 (механическая сверка чисел и дат) в ТЗ.

### 1.2. LLM-постобработка — с жёстким ограничением

Прогон распознанного текста через LLM для исправления артефактов допустим, но:

- LLM правит **только очевидные артефакты распознавания**;
- **не имеет права изменять числа, даты, номера статей и суммы** — они переносятся как есть;
- работает как обработчик предъявленного текста, не как источник знания (см. ТЗ, раздел 8.1).

> Риск без ограничения: модель «починит» текст правдоподобно, но юридически неверно —
> и это уже не поймать сверкой, потому что результат выглядит корректным.

### 1.3. Очистка служебных блоков (отдельная задача)

**Симптом.** В контент попадает:

```
55 % т ФА ‚5 [КАНЦЕЛЯРИЯ > \= /9Йрезидент %55 РосбЯйской Федерации В.Путин
Москва, Кремль 16 октября 2012 года №1
```

**Важно:** это **не ошибка распознавания**, а корректно распознанный служебный блок,
которому не место в контенте. Точность OCR его не уберёт ни при 98%, ни при 100%.

**Что сделать.**
- Отсекать при извлечении: подписи, печати, реквизиты канцелярии, колонтитулы, служебные
  символы. Опорные маркеры: «Президент Российской Федерации», «Москва, Кремль»,
  блок подписи на последней странице.
- Правило-гейт: если во фрагменте высокая доля мусорных символов (нераспознанные
  последовательности, обрывки латиницы вперемешку с кириллицей) — фрагмент **не
  публикуется**, карточка флажится в разбор.

> Один такой фрагмент в публичном посте бьёт по доверию сильнее, чем десять пропущенных
> законов.

## Приоритет 2 — Заменить «нарезку текста» на «сводку»

**Симптомы (все из одного корня — в пост идёт сырой фрагмент вместо смысла):**

1. **Обрывы посреди слова:** `...на условиях, пред`, `выполняемых иностранными п` —
   нарезка по N символов.
2. **Заголовок продублирован трижды:** в шапке, в описании, и в каждом пункте «Изменения».
   Съедает всё место, где должен быть смысл.
3. **Дельты нет.** По 13.19 КоАП оба пункта «Изменения» показывают почти один и тот же
   текст статьи (один с заголовком «Статья 13.19», другой без). Это не «было → стало»,
   а два куска одного текста. Читатель не может понять, что изменилось.

**Что сделать.**
- **Блок «Изменения» с сырыми фрагментами убрать полностью.** До итерации 3a настоящей
  дельты нет, а нарезка её не заменяет — только создаёт видимость.
- Вместо него — 1–2 предложения сводки от Gateway.
- **Никогда не обрезать по символам.** Либо законченная мысль, либо ничего.

## Шаблон карточки (итерация 1b)

```
№{номер}-ФЗ — {краткое название сути, 5–8 слов}

Принят: {дд.мм.гггг}
Опубликован: {дд.мм.гггг}
Вступает в силу: {дд.мм.гггг | «со дня опубликования» | «поэтапно, см. закон»}

{Суть: 1–2 предложения. Что меняется и для кого.}

Меняет: {название изменяемого акта}, {ст. N}
🔗 Первоисточник
```

**Порядок неслучаен:** юрист сканирует даты глазами и решает, читать ли дальше. Поэтому
даты выше сути, а не в подвале.

### Поля: откуда берём и как заполняем

| Поле | Источник | Правило |
|---|---|---|
| Номер ФЗ | `number` из API | Как есть. |
| Заголовок (суть) | Gateway | 5–8 слов, НЕ официальное название. Официальные названия длинные и однотипные («О внесении изменений в статью…») — не помогают выбрать, что читать. Полное название уйдёт по ссылке. |
| Принят | `documentDate` из API | Формат `дд.мм.гггг`. Есть в собранных данных, отдельным полем. |
| Опубликован | `publishDateShort` из API | Формат `дд.мм.гггг`. |
| Вступает в силу | Извлечение из текста | В API этого поля НЕТ. Извлекается отдельным шагом из текста закона, по частям (ТЗ, раздел 6) — разные статьи вступают в силу в разные даты. Одна дата → `дд.мм.гггг`. Со дня опубликования → так и пишем. Несколько дат → `поэтапно, см. закон`. Не извлеклось → `см. первоисточник`, поле не пропускаем. |
| Суть | Gateway | Максимум 2 предложения. Формула: *что стало иначе* + *кого касается*. Не пересказ статьи, не цитата. Не влезло в 2 предложения → модель не поняла закон → флажить, а не писать длиннее. |
| Меняет | Из названия закона | Название изменяемого акта + статья. До итерации 2 — из заголовка поправки; после — по распознанной связи. |
| Ссылка | `eoNumber` из API | Обязательна всегда. |

**Общее правило по датам:** все три поля выводятся всегда. Не извлеклось — пишем
`см. первоисточник`, но поле не пропускаем: читатель должен видеть, что мы про это помним.

## Примеры: было → стало

### Пример 1 — 14-ФЗ

**Было (~700 знаков, из них смысла ~0):**

> "О внесении изменения в статью 11.26 Кодекса Российской Федерации об административных
> правонарушениях" … Изменения: • ст. 11.26: Неправомерное осуществление каботажных
> автомобильных перевозок 1. Осуществление каботажных автомобильных перевозок, за
> исключением каботажных автомобильных перевозок грузов, выполняемых иностранными п

**Стало (~250 знаков):**

```
№14-ФЗ — Ответственность за каботажные автоперевозки

Принят: 28.02.2025
Опубликован: 28.02.2025
Вступает в силу: см. первоисточник

Изменён состав нарушения по неправомерным каботажным
автоперевозкам. Касается перевозчиков и логистических компаний.

Меняет: КоАП РФ, ст. 11.26
🔗 Первоисточник
```

### Пример 2 — 491-ФЗ

```
№491-ФЗ — Выходные дни по уходу за детьми-инвалидами

Принят: 05.12.2022
Опубликован: 05.12.2022
Вступает в силу: см. первоисточник

Изменён порядок предоставления дополнительных выходных
дней родителям и опекунам детей-инвалидов. Касается
работодателей и кадровых служб.

Меняет: Трудовой кодекс РФ, ст. 262
🔗 Первоисточник
```

Читатель за 5 секунд понимает, касается его или нет.

## Промпт для Gateway (генерация сути) — пример

Пример постановки, не финальная формулировка. Дорабатывается по результатам прогона.
Обязательными остаются три вещи: работа только по предъявленному тексту, ограничение
в 1–2 предложения и явный выход `НЕДОСТАТОЧНО ДАННЫХ`.

```
На входе: название закона, название изменяемого акта, номер статьи,
текст изменений.

Напиши 1–2 предложения: что стало иначе и кого это касается.

Только из предъявленного текста. Не цитируй закон.
Не добавляй оценок, прогнозов и «экспертов».
Не пиши «вносятся изменения» — пиши, что именно меняется.

Если из текста непонятно, что изменилось, — верни ровно:
НЕДОСТАТОЧНО ДАННЫХ
```

**Зачем последняя строка.** Она даёт модели легальный способ не выдумывать.
`НЕДОСТАТОЧНО ДАННЫХ` → карточка не публикуется, уходит в разбор. Это гейт в самой
простой рабочей форме.

## Порядок работ

1. Собрать эталонную выборку 20–30 ФЗ; прогнать бенчмарк OCR-движков и варианта с LLM;
   добиться CER/WER ≥ 98% и 100% по критичным элементам.
2. Реализовать отсечение служебных блоков + гейт на долю мусорных символов.
3. Убрать блок «Изменения» с сырыми фрагментами.
4. Сделать отдельный шаг извлечения даты вступления в силу (по частям).
5. Внедрить шаблон карточки со всеми полями + промпт сути; настроить обработку
   `НЕДОСТАТОЧНО ДАННЫХ`.
6. Прогнать на исторической выборке, глазами сверить 5–10 карточек с первоисточниками.
7. Переключить на актуальный период и прогнать на реальной неделе.

После этого итерация 1b закрыта честно, и можно идти в 2 (связь с изменяемым актом)
и 3a (дельта на «изложить в редакции»).
